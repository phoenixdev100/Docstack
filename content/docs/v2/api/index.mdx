The Meridian API is a REST API over HTTPS with JSON request and response bodies. This page covers the conventions every endpoint follows - read it once and the individual endpoint pages become predictable.

## Base URL

```text
https://api.meridian.dev/v2
```

All paths in this reference are relative to that base - `GET /projects` means `GET https://api.meridian.dev/v2/projects`.

## Authentication

Every request needs a Bearer key - see [Authentication](/docs/api/authentication) for key types and error cases.

```http
Authorization: Bearer mrnd_test_4f8e2c1a9b7d3e5f6a0c
```

## Conventions

**IDs** are prefixed opaque strings - `prj_`, `evt_`, `wh_`, `dlv_`, `key_`, `usr_`, `req_`. Treat them as immutable and never parse them.

**Timestamps** are RFC 3339 UTC: `2026-09-17T10:41:19Z`.

**Object envelopes** - every resource carries `"object": "<type>"` so payloads self-describe in logs and generic consumers.

**Nulls are explicit** - absent optional fields serialize as `null`, never omitted keys.

## Pagination

List endpoints use **cursor pagination** - stable under concurrent writes, unlike offsets.

<ParamTable
  label="Query parameters"
  params={[
    { name: "limit", type: "integer", description: "Items per page, 1–100.", default: "25" },
    { name: "cursor", type: "string", description: "Opaque cursor from a previous response's next_cursor." },
    { name: "order", type: "string", description: "asc or desc by created_at.", default: "desc" },
  ]}
/>

```json title="List response envelope"
{
  "object": "list",
  "data": [ /* … */ ],
  "has_more": true,
  "next_cursor": "cur_2nQ8kLm4xP"
}
```

When `has_more` is true, pass `next_cursor` back as `cursor` for the next page. SDKs auto-paginate: `client.projects.list()` iterates every page transparently.

## Filtering

List endpoints accept resource-specific filters alongside pagination. Common filters:

| Parameter | Applies to | Example |
| --- | --- | --- |
| `created_after` / `created_before` | all lists | `2026-09-01T00:00:00Z` |
| `status` | projects, deliveries, endpoints | `active`, `succeeded`, `failed` |
| `project_id` | events, webhooks | `prj_…` |
| `type` | events | `project.updated` |

## Rate limits

`600 req/min` (test) / `5,000 req/min` (live) per key, rolling window. Every response returns:

```http
X-RateLimit-Limit: 5000
X-RateLimit-Remaining: 4987
X-RateLimit-Reset: 1758092460
```

On `429`, honor `Retry-After`. Details in [Error handling](/docs/guides/error-handling#rate-limits).

## Idempotency

`POST` accepts `Idempotency-Key` - replaying a key within 24h returns the original response, no duplicate write. SDKs attach one automatically; send your own to correlate with your domain operations.

```http
Idempotency-Key: provision-acme-2026-09-17-001
```

## Versioning

- The API version is in the path (`/v2`). Breaking changes only ship under a new version path.
- Additive changes - new fields, new enum values, new endpoints - land in the current version without notice; clients must tolerate unknown fields.
- Deprecations are announced in the [changelog](/docs/changelog) with at least 6 months' notice and a migration window.
- `Meridian-Version` response header echoes the exact version that served the request.

## Request and response format

- Bodies are `application/json; charset=utf-8`.
- Maximum request size: **1 MB**; webhook payloads cap at 256 KB.
- All timestamps UTC; all amounts/counts are integers.
- Every response carries `Meridian-Request-Id` - quote it in support requests.

## The error contract

Failures return a non-2xx status plus a structured error object:

```json title="Error shape"
{
  "error": {
    "type": "invalid_request",
    "code": "parameter_missing",
    "message": "Missing required parameter: name.",
    "param": "name",
    "request_id": "req_8fK2mPx4vL"
  }
}
```

Branch on `code`, not `message`. Full catalog: [Errors](/docs/api/errors).
